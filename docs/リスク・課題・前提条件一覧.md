# リスク・課題・前提条件一覧

## 1. 評価方法

- 影響度・発生可能性は「高・中・低」の暫定評価。
- リスク所有者と期限は関係者合意後に確定する。
- 実装・契約・規程が未確認のため、残存リスクを「解消済み」とはしない。

## 4. 前提条件

1. Entra ID／HENNGE ONE、AppSuite、desknet's NEO、OneDrive、DirectCloud、Lightblueの採用・契約は候補方針であり、利用可能性を別途確認する。
2. 監査判断、重要度、監査意見、是正完了は権限を持つ人が決定する。
3. 組織・社員マスターが正確かつ適時に更新される。
4. 被監査部門は指定期限・形式で証憑を提出し、真正性に責任を持つ。
5. 本番前に業務受入、セキュリティ、復元、移行・切戻し試験を完了する。

## 5. 見直し

設計審査、PoC、契約、規程改定、重大障害、監査指摘の発生時に更新し、各リスクの対応前・対応後評価、承認者、期限、証跡を追記する。
