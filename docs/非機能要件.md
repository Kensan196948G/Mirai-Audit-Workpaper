# 非機能要件

## 1. 適用方針

既存資料は可用性、バックアップ、ログ、暗号化、脆弱性管理を要求しているが、数値目標は未確定である。本書の数値は調達・設計比較に用いる**暫定目標案**であり、契約SLAや達成実績ではない。

## 3. 前提となる測定条件

- 同時利用者、年間監査数、証憑件数・容量、ネットワーク帯域は未測定。
- SaaS各製品の標準SLA、バックアップ、ログ保持期間、エクスポート仕様は契約候補ごとに確認する。
- 目標は監査繁忙期、取締役会前、災害時の利用を考慮して見直す。
- 「応答時間」はネットワーク、認証、外部サービス連携を含む利用者体感で測定する。

## 4. 合否原則

必須要件に未達がある場合は原則として本番移行不可とする。例外は、リスク、期限、代替統制、責任者、解消日を記載し、監査役・情報セキュリティ責任者・システム責任者が承認した場合に限る。
