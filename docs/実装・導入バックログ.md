# 実装・導入バックログ（順序付き）

本プロジェクトは、文書（構想・要件・設計）に加えて、要件定義書 MAW-RD-001 の主要機能を実装したアプリ（app/）を保有します。
本書は、正式な社内決定（規程・権限・保存年限・採用製品）と受入試験を経て本番運用（実データ投入）へ進むための
優先度順バックログです。「検証中」は app/ に実装・テスト済みで、本番受入（UAT）待ちであることを示します。
「未着手」は本番運用前に追加実装が必要な項目です。

## 凡例

- **P0**: 障害・漏えい・破損・認証問題（本番運用を妨げる重大事項）
- **P1**: 主要業務の欠落・不能（監査業務の継続に必須）
- **P2**: 代替率と価値を高める改善・機能
- **P3**: 将来構想・任意機能
- **状態**: 未着手／設計中／実装中／検証中／受入済み

## 前提（すべての着手前に必要）

1. 監査役会規程・監査規程・職務分掌・決裁権限との照合（[リスク・課題・前提条件一覧](リスク・課題・前提条件一覧.md) I-01）
2. 保存年限・廃棄承認（I-02）
3. 採用製品の決定と契約（I-03、ARC-01〜05）
4. 非機能目標の正式値承認（I-04、NFR-01〜18）
5. 個人情報・AI利用の基準承認（I-05、I-06）

## 対象外（受入条件付きでバックログ外）

- 取締役会決議管理、内部通報案件の詳細管理、CSR集計 — 別システム構想（[システム要件一覧](../システム要件一覧.md)）が対象
- 監査判断・法的評価・処分の自動決定 — 本プロジェクトの基本方針で禁止

## 更新ルール

- 各作業の着手・完了時、および [変更履歴](変更履歴.md) に記録を追記する。
- 受入条件は [要件定義書](../要件定義書.html) の AC-ID と [テスト計画・受入基準](テスト計画・受入基準.md) の UAT-ID に対応させる。
- 本バックログは [導入・教育・定着計画](導入・教育・定着計画.md) の段階導入案（試作→試行→展開）と同期させる。
