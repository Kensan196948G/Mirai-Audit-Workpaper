# テスト計画・受入基準

## 1. 目的

監査業務が安全かつ追跡可能に行えることを、本番移行前に業務・データ・権限・復旧の観点で確認する。要件定義書 MAW-RD-001 の主要機能の PoC 実装（app/: Cloudflare Workers + D1）が存在し、自動テスト57件・ビルド・リンク検証は PASS 済み（CI: .github/workflows/ci.yml）。本書の UAT-01〜10 は本番移行（実データ投入）前の業務受入シナリオであり、関係者による受入完了をもって合格とする。

## 2. テスト段階

| 段階 | 主体 | 対象 | 完了条件 |
|---|---|---|---|---|
| 設定・単体 | 構築担当 | フィールド、入力制御、通知、権限 | 全必須ケース合格 |
| 結合 | 構築担当・管理者 | SSO、AppSuite、desknet's NEO、OneDrive、DirectCloud、ログ | データ欠落・重複・権限逸脱なし |
| システム | QA | 機能、性能、障害、セキュリティ | 重大欠陥0、必須要件合格 |
| 業務受入 | 監査役、総務部、被監査部門代表 | 実業務シナリオ | 役割別責任者が承認 |
| 移行・復旧 | 運用・監査役 | 移行、バックアップ、復元、切戻し | 件数・ハッシュ一致、目標時間内 |

## 4. セキュリティ・品質試験

- 認証回避、水平・垂直権限逸脱、期限切れ共有、直接URL、API認可を確認する。
- ファイル名・本文・添付への悪性入力、マルウェア、過大ファイル、二重送信を確認する。
- 監査ログの網羅性、時刻同期、検索性、改変防止、保存・廃棄を確認する。
- 対象ブラウザ、拡大表示、キーボード操作、読み上げ、エラー表示を確認する。
- 負荷、容量上限、連携停止、通知失敗、再送、復旧後整合性を確認する。

## 5. 欠陥区分と移行判定

| 重要度 | 例 | 本番移行 |
|---|---|---|---|---|
| Blocker | 情報漏えい、データ消失、認証回避、正本改変 | 不可 |
| Critical | 主要業務不能、誤承認、監査証跡欠落 | 不可 |
| Major | 代替手段はあるが重要業務に影響 | 原則不可。例外承認が必要 |
| Minor | 軽微な表示・操作性 | 期限・責任者を定めて可 |

必須ケース100%合格、Blocker/Critical 0件、未解決リスクの承認、移行・切戻しリハーサル完了を本番移行条件とする。
