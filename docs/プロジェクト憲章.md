# プロジェクト憲章

## 1. 文書の位置付け

本書は、監査業務・証跡管理基盤（Mirai Audit Workpaper）の目的、意思決定範囲、成功条件を共有するための起点である。現時点は構想・要件定義段階であり、稼働システムの存在を示すものではない。

## 2. 目的

- 年度監査計画から改善確認までを一貫した案件単位で管理する。
- 監査手続、証憑、結論、レビュー記録のつながりを残す。
- 監査役会、監査役、総務部、被監査部門の責任境界を明確にする。
- 機密性、独立性、改ざん防止、説明可能性を保つ。
- 通知や転記の負担を減らし、判断と対話に時間を使えるようにする。

## 3. 対象範囲

### 対象

年度監査計画、個別監査、証憑依頼・受領、監査手続、ヒアリング、監査調書、発見事項、レビュー・承認、報告、改善計画、フォローアップ、確定記録の保存、監査ログ、権限管理。

### 対象外

監査判断の自動化、法的評価や処分の自動決定、会計監査人の専用システムの置換、内部通報案件の詳細管理、取締役会決議管理、既存文書管理基盤そのものの全面置換。

## 4. 成功条件

| 観点 | 成功条件（正式値は要承認） |
|---|---|
| 完全性 | 必須調書・必須証憑・レビュー記録に欠落がない |
| 追跡性 | 指摘から根拠となる調書・証憑へたどれる |
| 期限 | 依頼・レビュー・改善の期限超過が可視化される |
| 独立性 | 被監査部門が監査側の非公開検討情報を閲覧できない |
| 説明可能性 | 誰が、いつ、何を変更・承認・出力したか確認できる |
| 継続性 | バックアップと復旧手順が試験されている |

## 5. 意思決定と承認

業務ルールは監査役会、運用支援は総務部、セキュリティは情報セキュリティ責任者、個人情報は個人情報保護責任者、システム変更は指定された変更承認者が確認する。最終的な体制と氏名は未確定である。

## 6. 制約

- 社内規程、監査基準、保存年限、決裁権限が最優先となる。
- AIは要約や検索補助に限定し、監査判断を代替しない。
- 個人情報・機密情報を未承認の外部サービスへ投入しない。
- 本番移行は受入試験、権限棚卸し、バックアップ復元試験、利用者教育の完了後に承認する。

## 7. 現在の承認状態

本書は設計たたき台であり、正式承認前である。プロジェクト責任者、予算、開始日、リリース日、採用製品は未確定。
