# セキュリティ・個人情報保護方針

## 1. 目的と適用範囲

監査計画、調書、証憑、発見事項、被監査部門の回答、利用ログを対象に、機密性・完全性・可用性と本人の権利を守る。正式な法令評価、社内規程、委託契約の確認は未実施であり、本書だけで法令遵守を保証しない。

## 2. 基本原則

1. 目的限定・データ最小化：監査目的に必要な情報だけを収集する。
2. Need-to-know：所属ではなく案件担当、役割、機密区分、利益相反でアクセスを決める。
3. 職務分離：作成、レビュー、承認、システム管理、ログ監査を可能な限り分ける。
4. 正本保護：確定調書・証憑は版固定し、上書き・無承認削除を防ぐ。
5. 人による判断：AIに監査結論、人物評価、処分、完了判定を委ねない。

## 3. 情報分類案

| 区分 | 例 | 取扱い |
|---|---|---|
| 公開 | 公表済み監査報告 | 承認済み版のみ公開 |
| 社内限定 | 一般手順、教育資料 | 組織認証済み利用者に限定 |
| 機密 | 監査計画、依頼、回答、是正状況 | 案件関係者のみ、出力制御 |
| 極秘 | 未確定所見、個人情報を含む証憑、重大不正・訴訟情報 | 個別承認、強化ログ、持出し原則禁止 |

## 4. セキュリティ統制

| 領域 | 必須統制 |
|---|---|
| ID | Entra ID／HENNGE ONEのSSO・MFA、共有ID禁止、退職即時停止 |
| 権限 | RBACと案件・機密属性を組み合わせ、四半期および監査終了時に棚卸し |
| 特権 | 期限付き付与、別ID、承認、操作記録。技術管理者は原則として調書本文を閲覧しない |
| 端末 | 組織管理端末、画面ロック、暗号化、マルウェア対策、必要に応じダウンロード禁止 |
| 通信・保存 | 暗号化、秘密情報の集中管理、外部共有の期限・相手・範囲を制限 |
| ログ | 閲覧、検索、変更、承認、印刷、出力、共有、権限変更、削除要求を記録し改変防止 |
| 脆弱性 | SaaS保証報告の確認、設定診断、連携部の診断、修正期限のリスク別管理 |
| 委託先 | 再委託、保存国、漏えい通知、削除、監査権、終了時返却を契約確認 |

## 5. 個人情報保護

- 収集前に利用目的、対象、項目、保存期間、閲覧者を明確にする。
- 人事・健康・評価・通報等の情報は、監査に必要な最小範囲に絞り、可能なら匿名化・仮名化する。
- 証憑に不要な個人番号、口座、健康情報等が含まれる場合は提出前マスキングを依頼する。
- 開示・訂正・利用停止等の請求窓口と、監査証跡保全・法的義務との調整手順を個人情報保護責任者が決める。
- 国外保存・国外アクセス、第三者提供、共同利用の有無は製品・契約ごとに確認する。

## 6. AI利用ガードレール

| 可 | 条件付き | 禁止 |
|---|---|---|
| 公開資料の要約、承認済みテンプレート検索 | 許可済み・マスキング済み証憑の要約、類似論点候補 | 個人の不正・性格・健康等の推定、監査結論の自動確定 |
| 人が確認する文章校正 | 根拠リンクと利用ログを残す分類支援 | 通報者情報、認証情報、未公表重大情報の投入 |

AI出力は誤りを含み得る参考情報として表示し、原文への参照、利用モデル・日時、入力範囲、確認者を記録する。

## 7. インシデント対応

誤送信、権限逸脱、不正閲覧、マルウェア、データ消失、AIへの誤投入を検知した場合、利用停止・証拠保全・影響確認・責任者報告・本人／当局／取引先への通知要否判断・再発防止を行う。報告期限と連絡網は[運用・保守・障害対応計画](運用・保守・障害対応計画.md)で確定する。

## 8. 導入前の必須確認

- 監査規程、情報管理規程、個人情報保護規程、文書保存規程との整合。
- 製品ごとの保存場所、暗号鍵、バックアップ、ログ保持、管理者アクセス、削除証明。
- 機密区分、保存年限、AI投入禁止情報、外部共有の承認者。
